# GPT素材生成ループ

ChatGPTで画像を1点ずつ生成し、ユーザーがGitHubの `inbox/` にアップロードした画像を、このスキルのスクリプトで取り込んでリポジトリに保存する。これを `assets.json` の全素材(41点)が揃うまで繰り返す。

ChatGPTの操作とGitHubへのアップロードはユーザーが行う。Claudeはプロンプトの提示、取り込み、品質チェック、コミット、進捗管理を担当する。

## 作業環境

- Claude Code はクラウドで動いており(iPhoneのClaudeアプリから操作)、ユーザーのパソコンやGoogleドライブには触れない
- 画像の受け渡しはすべてGitHub経由。ユーザーがGitHubの `main` ブランチの `inbox/` にアップロードし、Claudeが取り込んで作業ブランチにコミットする
- 作業ブランチは最後にプルリクエストで `main` にマージしてもらう

## 前提

- **1回の生成で描かせるのは1点だけ。** ChatGPTに複数を頼むと、1枚の画像にまとめて描かれてしまう。プロンプトは必ず1点ずつ渡す
- **すべての素材を同じChatGPTのチャットで続けて生成する。** 前の画像を覚えているので絵柄がそろい、基準画像の再添付も不要になる
- 生成回数の上限に達したら、その日は止めてよい。進捗は `status.json` に残るので、次回そのまま再開できる

## 初回セットアップ

1. クラウド環境で依存ライブラリが入っているか確認: `python -c "import PIL, numpy, scipy"`。無ければ `pip install pillow numpy scipy`。何度も使うなら、Claude Codeのクラウド環境の設定(setup script)に同じコマンドを入れておくようユーザーに勧める
2. キャラクターの設定を変えたいときだけ、`config.example.json` を `config.json` にコピーして `character` を書き換える。無ければ初期値で動く
3. `python scripts/asset_loop.py status` で動作確認

以降のコマンドはすべてこのスキルのフォルダで実行する。

## ユーザーに伝える、画像の上げ方

最初に一度、次の手順を説明しておく。

1. ChatGPTアプリで生成した画像を長押しして「写真に保存」
2. SafariでGitHubを開き、このリポジトリの `inbox` フォルダへ移動
3. 「Add file」→「Upload files」→ 写真から画像を選ぶ(複数まとめて選んでよい)
4. 「Commit directly to the main branch」のままコミット
5. Claudeに「アップした」と伝える

ファイルのアップロードはSafariでGitHubのサイトを開いて行うのが確実。

## 取り込みの前後に毎回やること

- **取り込みの前**: `git fetch origin main && git merge origin/main` で、ユーザーが上げた画像を作業ブランチに取り込む
- **取り込みの後**: `git add -A && git commit -m "素材: <素材ID>" && git push` でコミットして送る。inboxの画像は取り込み時に削除されるので、その削除もコミットに含まれる

## ループの手順

### フェーズA: 基準の車(絵柄の基準)

最初の素材 `ref_car` は、以降すべての絵柄の基準になる。**ここは気に入るまで何度でも作り直す。** 妥協すると全素材に波及する。

1. `python scripts/asset_loop.py prompt ref_car` を実行し、出力されたプロンプトをそのままユーザーに渡す
2. ユーザーに伝える: 「ChatGPTで**新しいチャット**を開き、このプロンプトを貼ってください。できた画像をGitHubの `inbox` にアップロードしたら教えてください」
3. 連絡が来たら `main` を取り込んでから `python scripts/asset_loop.py ingest` を実行
4. 出力されたプレビュー画像を開いて自分でも確認し、下の「品質チェック」を行う
5. ユーザーに見せて採用か確認する
   - 採用 → `python scripts/asset_loop.py approve ref_car` してコミット。基準画像は `assets-src/reference/style_reference.png` に保存される
   - 不採用 → どこが気に入らないか聞き、「作り直し用の追記」から該当する文を選んでユーザーに渡す。同じチャットで送ってもらい、新しい画像をアップロードしてもらう。`reset ref_car` してから3へ戻る

### フェーズB: 残りの素材(グループ単位で進める)

素材はグループ(車の色違い、障害物、草原など)に分かれている。`status` で次の素材を確認し、1グループずつ進める。

1. 次の素材について `prompt <素材ID>` を実行し、プロンプトをユーザーに渡す
2. ユーザーに伝える: 「**基準の車を作ったのと同じチャット**に貼ってください」。別のチャットになった場合は、GitHubの `assets-src/reference/style_reference.png` を保存して添付してから貼ってもらう
3. 連絡が来たら `main` を取り込んで `ingest` を実行し、プレビューを自分で開いて品質チェックしてからコミットする
   - 問題なし → そのまま次の素材の1へ(承認はグループの最後にまとめて行う)
   - 問題あり → `reset <素材ID>` し、追記文を渡して作り直してもらい、3へ
4. グループの最後の素材まで終わったら `preview-all --group <グループID>` を実行してコミットし、GitHub上の `assets-src/preview/group_<グループID>.png` を開いてもらってグループの一覧を確認してもらう
   - OK → `approve <グループID>` でまとめて完了にする
   - 直したい素材がある → その素材を `reset` して作り直し、再度一覧を見せる
5. ユーザーが「上限」「今日はここまで」と言ったら、`status` の結果を要約して終える(完了した素材と、次に再開する素材)

**まとめて取り込む場合**: 同じチャットで数点続けて生成し、まとめてアップロードしてもらってもよい。`ingest --all` はファイル名の順に、未着手の素材へ順番に割り当てる。iPhoneの写真は保存順に `IMG_0901`、`IMG_0902` と番号が増えるので、生成した順に写真へ保存していれば順番は合う。ファイル名を素材ID(例: `frog.png`)にしておけば、順番に関係なくその素材として取り込む。プレビューで絵と名前が合っているか必ず確かめる。

### 完了

全素材が揃ったら:

1. `check` で、DESIGN.md 13章の素材がすべて `assets/img/` と `assets/icons/` にあるか確認
2. `preview-all` で全素材の一覧を作り、ユーザーに見せる
3. 絵柄がそろっていない素材があれば、その素材だけ `reset` して作り直す

## 品質チェック

プレビュー画像は、素材を「市松模様の上」と「道路の灰色の上」に並べてある。以下を確認する。

| 確認項目 | 見るところ |
| --- | --- |
| 透過 | 市松模様が素材の周りに見えるか。四角い背景が残っていないか |
| ふち | 灰色の上で、素材のふちにピンクや白のにじみが出ていないか |
| 中身 | 指定した物が1つだけ描かれているか。余計な物(地面、背景の風景など)がないか |
| 名前 | 取り込み結果の素材名と絵が合っているか |
| 線の細さ | 細い線・細かい模様がないか(縮小すると見えなくなり、チラつく) |
| 絵柄 | 基準の車と同じ塗り方・丸み・色の雰囲気か |
| オリジナル性 | 既存のキャラクターや商品に似ていないか |
| 文字 | 文字・数字・ロゴが入っていないか |

`ingest` の出力に `WARN` や `NG` が出たら、その内容を必ずユーザーに伝える。

## 作り直し用の追記

同じチャットに送ってもらう文。問題に合わせて選ぶ。

| 問題 | 追記する文 |
| --- | --- |
| 背景が透明でない | 背景を完全に透明にして、もう一度描いてください。透明にできない場合は背景全体を単色のマゼンタ(#FF00FF)で塗りつぶしてください。 |
| 余計な物が描かれた | 指定した物を1つだけ描き、地面・背景の風景・ほかの物は描かないでください。 |
| 線が細い・模様が細かい | 細い線と細かい模様をすべてなくし、形をもっと太く大きく、単純にしてください。輪郭線は描かないでください。 |
| 絵柄がずれた | 最初に採用した赤い車の画像と、塗り方・丸み・色の明るさをそろえて描き直してください。 |
| 既存キャラに似ている | 特定のキャラクターに似ないよう、形と配色を変えた完全オリジナルのデザインにしてください。 |
| 文字が入った | 文字、数字、ロゴをすべて取り除いてください。 |
| 角度が違う | 角度は(プロンプトにある角度)にそろえてください。 |
| 複数枚ぶんが1枚にまとまった | 1つの物だけを、画像の中央に大きく1つ描いてください。 |

## コマンド一覧

| コマンド | 内容 |
| --- | --- |
| `status` | グループごとの進捗と次の素材 |
| `prompt <素材ID>` | その素材の完成プロンプトを表示 |
| `ingest [--sheet <素材ID>]` | inboxの画像(1枚)を取り込み、透過処理してWebP保存。省略時は、ファイル名が素材IDならその素材、違えば未着手の最初の素材 |
| `ingest --all` | inboxの画像をファイル名の順に、未着手の素材へ順番に取り込む |
| `approve <素材ID またはグループID>` | 完了にする。グループIDなら、そのグループの確認待ちをまとめて完了 |
| `reset <素材ID>` | 未着手に戻す |
| `check` | 必要な素材がすべて揃っているか |
| `preview-all [--group <グループID>]` | 取り込んだ素材の一覧画像 |

## 保存先(すべてリポジトリ内)

| 保存先 | 中身 |
| --- | --- |
| `inbox/` | ユーザーがアップロードする場所。取り込むと画像は削除される |
| `assets/img/<dir>/<name>.webp` | アプリが読む素材 |
| `assets/icons/icon-*.png` | アプリアイコン |
| `assets-src/reference/style_reference.png` | 基準の車(別チャットで添付し直す用) |
| `assets-src/preview/` | 確認用のプレビュー画像 |

元画像は基準の車以外は残さない(リポジトリが重くなるため)。元画像はChatGPTの履歴とiPhoneの写真に残っている。`assets-src/` と `inbox/` はNetlifyには公開されない(`netlify.toml` でアプリのファイルだけを公開している)。

## 注意

- `assets.json` の素材名とディレクトリは DESIGN.md 13章と一致させてある。変えるときは両方を直す
- 素材の中身(プロンプト)を変えたいときは `assets.json` を編集する。共通の絵柄指定は `style` と `background` にある
- 取り込み時、画像の中の物のかたまりを1つにまとめて切り出す。離れた部品(気球のかごなど)は自動で1つにまとめ、`WARN` で知らせる
