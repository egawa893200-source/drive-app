# GPT素材生成ループ

ChatGPTで画像を1点ずつ生成し、ユーザーがGitHubの `inbox/` にアップロードした画像を、このスキルのスクリプトで取り込んでリポジトリに保存する。これを `assets.json` の全素材(47点)が揃うまで繰り返す。ChatGPTには最初にリストを渡し、ユーザーは「次」と送るだけで続けて描かせる(「次」ループ)。

ChatGPTの操作とGitHubへのアップロードはユーザーが行う。Claudeはプロンプトの提示、取り込み、品質チェック、コミット、進捗管理を担当する。

## 作業環境

- Claude Code はクラウドで動いており(iPhoneのClaudeアプリから操作)、ユーザーのパソコンやGoogleドライブには触れない
- 画像の受け渡しはすべてGitHub経由。ユーザーがGitHubの `main` ブランチの `inbox/` にアップロードし、Claudeが取り込んで作業ブランチにコミットする
- 作業ブランチは区切りのよいところ(グループごとなど)でプルリクエストにして `main` にマージしてもらう
- APIキーは使わない。画像はユーザーがChatGPTアプリで作る

## 前提

- **APIは使わない。** 個人情報の漏えいなどの心配があるので、画像はユーザーがChatGPTアプリで作る(ユーザーの判断)。APIキーを頼んだり、APIを呼ぶ仕組みを足したりしない
- **1回の生成で描かせるのは1点だけ。** ChatGPTに複数を頼むと、1枚の画像にまとめて描かれてしまう
- **すべての素材を同じChatGPTのチャットで続けて生成する。** 前の画像を覚えているので絵柄がそろう
- 生成回数の上限に達したら、その日は止めてよい。進捗は `status.json` に残るので、次回そのまま再開できる

## 「次」ループ(ふだんはこれを使う)

1点ずつプロンプトを貼るのは手間なので、**決まりと番号付きのリストを最初に1回だけChatGPTに貼り、あとは「次」と送るだけ**で、ChatGPTがリストの順に1枚ずつ描くようにする。

1. `chatgpt-list` を実行し、出力された文(その1)をユーザーに渡す。長い会話だとChatGPTが最初の指示を忘れやすいので、リストは約16点ずつ3つに分けてある
2. ユーザーに伝える:
   - ChatGPTで**新しいチャット**を開き、この文を貼って送る。1番の赤い車が出てくる
   - **1番の車は、気に入るまで「やり直し」と送って作り直す**(全部の絵の見本になるため)。直してほしいところがあれば「やり直し 窓をもっと大きく」のように続けて書く
   - 気に入ったら「次」と送る。以降は「次」を送るたびに1枚ずつ描かれる。気に入らない絵は「やり直し」
   - 描いた絵は、そのつど長押しして「写真に保存」。**描いた順に保存する**
   - その1のリストを描き終えたら、Claudeに「その1が終わった」と伝える
3. ユーザーに、保存した絵をまとめてGitHubの `inbox` にアップロードしてもらう(下の「画像の上げ方」。写真を複数まとめて選んでよい)
4. `main` を取り込み、`inbox-preview` で一覧(`assets-src/preview/inbox.png`)を作って**自分で見る**。番号と絵を見比べ、どの絵がどの素材か確かめる
   - 順番がずれている・足りない・余分がある場合は、ファイルを素材IDの名前に変える(例: `git mv inbox/IMG_0915.PNG inbox/frog.png`)。余分な絵は消す
5. `ingest --all` で取り込み、グループごとに `preview-all --group <グループID>` を作ってコミットし、ユーザーに見てもらう(下の「フェーズB」の4と同じ)
   - 直したい素材があれば `reset <素材ID>` し、ChatGPTの同じチャットで「◯番をやり直し(注文)」と送ってもらう
6. 基準の車は、最初の取り込みのあと `approve ref_car` しておく(`assets-src/reference/style_reference.png` に残り、別のチャットで続けるときに添付できる)
7. `chatgpt-list --part 2` で続きを渡し、2〜5をくり返す。`chatgpt-list` は未着手の素材だけを載せるので、途中で止まっても続きから出せる

ChatGPTが番号を飛ばしたり、2枚まとめて描いたりしたら「◯番だけを描いて」と送ってもらう。途中でチャットが変わった場合は、`style_reference.png` を添付して、`chatgpt-list` の続きを貼ってもらう。

### Googleドライブについて

ユーザーの控えとして、作った絵をGoogleドライブに保存するのは自由。ただし**ドライブから取り込むことはできない。** このセッションのGoogleドライブの接続は、ファイルを会話の中の文字として受け渡すしくみで、ChatGPTの絵1枚(1〜2MB)が数百万文字になり、受け取れる量を大きく超える。取り込み用の受け渡しは、GitHubの `inbox` を使う。

`inbox` の絵はGitHub上で公開されるが、取り込んだ素材はどのみちアプリとして公開されるので、公開される範囲は変わらない。ChatGPTで作った絵以外(家族の写真など)は上げないようにだけ伝える。

## 初回セットアップ(毎回の始めにも)

1. 依存ライブラリの確認: `python -c "import PIL, numpy, scipy"`。無ければ `pip install pillow numpy scipy`。何度も使うなら、Claude Codeのクラウド環境の設定(setup script)に同じコマンドを入れておくようユーザーに勧める
2. **`python scripts/asset_loop.py sync-check` を実行する。** `assets.json` とアプリのコード(`js/`)の素材の名前・保存先・縦横の比がずれていないか確かめる。`NG` が出たら、素材づくりの前に `assets.json` を直す(コードが正。下の「アプリでの使われ方」も読む)
3. キャラクターの設定を変えたいときだけ、`config.example.json` を `config.json` にコピーして `character` を書き換える。無ければ初期値で動く
4. `python scripts/asset_loop.py status` で進捗を確認

以降のコマンドはすべてこのスキルのフォルダで実行する。

## アプリでの使われ方と、描き方の決まり

素材はアプリの中で次のように使われる。プロンプトはこれに合わせてあるので、作り直しのときもこの決まりを守る。

- **縦横の比はコードで決まっている。** アプリは画像を、コードで決めた比(`assets.json` の `aspect` = 縦/横)に引き伸ばして描く。プロンプトで形を指定し、取り込みでも余白を足して比をそろえる。絵の形が大きく違うと `WARN` が出る(ゆがみはしないが、アプリで小さく見える)
- **地面に立つ物は、画像の下端が地面になる。** 取り込みでは下に余白を入れない(`anchor: bottom`)。空に浮かぶ物(雲・気球・かもめ・月)と、自車・おやすみの絵は中心基準
- **牛・犬・アヒルは、右を向いた横向き(顔だけ少しこちら)。** クラクションを鳴らすと左右反転して「振り向く」動きになるので、正面向きだと反転しても変化が見えない
- **小鳥とフクロウは、とまっている姿。** クラクションで飛び立つ(同じ絵が上に動いて消える)
- **電車は前と後ろが同じ形の車両1両。** 同じ絵を3両つなげ、右にも左にも走らせる
- **遮断機は上がった姿だけ。警報機のランプは消えている。** アプリでは遮断機を下ろさず、点滅や赤い警告も出さない(DESIGN.md 18章)
- **車庫は横に広く、入り口が大きく開いている。** 最後に画面いっぱいに映り、自車がそこへ入っていく
- 素材が無くてもアプリはプレースホルダーの図形で動く。1点ずつ差し替わっていく

## 画像の上げ方(ユーザーに伝える)

最初に一度、次の手順を説明しておく。

1. ChatGPTアプリで生成した画像を長押しして「写真に保存」
2. SafariでGitHubを開き、このリポジトリの `inbox` フォルダへ移動
3. 「Add file」→「Upload files」→ 写真から画像を選ぶ(複数まとめて選んでよい)
4. 「Commit directly to the main branch」のままコミット
5. Claudeに「アップした」と伝える

ファイルのアップロードはSafariでGitHubのサイトを開いて行うのが確実。

## 取り込みの前後に毎回やること

- **取り込みの前**: `git fetch origin main && git merge origin/main` で、ユーザーが上げた画像を作業ブランチに取り込む
- **取り込みの後**: `git add -A && git commit -m "素材: <素材ID>" && git push` でコミットして送る。inboxの画像は取り込み時に削除されるので、その削除もコミットに含まれる

## 1点ずつ進める手順(「次」ループがうまくいかないとき)

### フェーズA: 基準の車(絵柄の基準)

最初の素材 `ref_car` は、以降すべての絵柄の基準になる。**ここは気に入るまで何度でも作り直す。** 妥協すると全素材に波及する。

1. `python scripts/asset_loop.py prompt ref_car` を実行し、出力されたプロンプトをそのままユーザーに渡す
2. ユーザーに伝える: 「ChatGPTで**新しいチャット**を開き、このプロンプトを貼ってください。できた画像をGitHubの `inbox` にアップロードしたら教えてください」
3. 連絡が来たら `main` を取り込んでから `python scripts/asset_loop.py ingest` を実行
4. 出力されたプレビュー画像を開いて自分でも確認し、下の「品質チェック」を行う
5. ユーザーに見せて採用か確認する
   - 採用 → `python scripts/asset_loop.py approve ref_car` してコミット。基準画像は `assets-src/reference/style_reference.png` に保存される
   - 不採用 → どこが気に入らないか聞き、「作り直し用の追記」から該当する文を選んでユーザーに渡す。同じチャットで送ってもらい、新しい画像をアップロードしてもらう。`reset ref_car` してから3へ戻る

### フェーズB: 残りの素材(グループ単位で進める)

素材はグループに分かれている。`status` で次の素材を確認し、1グループずつ進める。

| グループ | 素材 |
| --- | --- |
| cars | 車の色違い(青・黄・白) |
| obstacles | 障害物(水たまり・落ち葉・カエル・ボール・アヒル親子・カメ) |
| animals | 生き物(小鳥・犬・アヒル)。クラクションに反応し、どうぶつボタンでも出てくる |
| roadside | 道ばたの植物(全場面共通) |
| meadow / sea / town / night | 4つの場面の物 |
| crossing | 踏切(電車・遮断機・警報機) |
| far_day / far_evening | 遠景と雲 |
| ending | おわりの演出(車庫・おやすみ) |
| icon | アプリアイコン |

1. 次の素材について `prompt <素材ID>` を実行し、プロンプトをユーザーに渡す
2. ユーザーに伝える: 「**基準の車を作ったのと同じチャット**に貼ってください」。別のチャットになった場合は、GitHubの `assets-src/reference/style_reference.png` を保存して添付してから貼ってもらう
3. 連絡が来たら `main` を取り込んで `ingest` を実行し、プレビューを自分で開いて品質チェックしてからコミットする
   - 問題なし → そのまま次の素材の1へ(承認はグループの最後にまとめて行う)
   - 問題あり → `reset <素材ID>` し、追記文を渡して作り直してもらい、3へ
4. グループの最後の素材まで終わったら `preview-all --group <グループID>` を実行してコミットし、GitHub上の `assets-src/preview/group_<グループID>.png` を開いてもらってグループの一覧を確認してもらう
   - OK → `approve <グループID>` でまとめて完了にする
   - 直したい素材がある → その素材を `reset` して作り直し、再度一覧を見せる
5. ユーザーが「上限」「今日はここまで」と言ったら、`status` の結果を要約して終える(完了した素材と、次に再開する素材)

**まとめて取り込む場合**: 同じチャットで数点続けて生成し、まとめてアップロードしてもらってもよい。`ingest --all` はファイル名の順に、未着手の素材へ順番に割り当てる。iPhoneの写真は保存順に `IMG_0901`、`IMG_0902` と番号が増えるので、生成した順に写真へ保存していれば順番は合う。ファイル名を素材ID(例: `frog.png`)にしておけば、順番に関係なくその素材として取り込む。プレビューで絵と名前が合っているか必ず確かめる。

### 完了

全素材が揃ったら:

1. `sync-check` と `check` で、コードが使う素材がすべて `assets/img/` と `assets/icons/` にあるか確認
2. `preview-all` で全素材の一覧を作り、ユーザーに見せる
3. 絵柄がそろっていない素材があれば、その素材だけ `reset` して作り直す
4. プルリクエストを作り、デプロイプレビューで、プレースホルダーが実際の絵に替わっているかをiPhoneで確かめてもらう

## 品質チェック

プレビュー画像は、素材を「市松模様の上」と「道路の灰色の上」に並べてある。以下を確認する。

| 確認項目 | 見るところ |
| --- | --- |
| 透過 | 市松模様が素材の周りに見えるか。四角い背景が残っていないか |
| ふち | 灰色の上で、素材のふちにピンクや白のにじみが出ていないか |
| 中身 | 指定した物が1つだけ描かれているか。余計な物(地面、背景の風景など)がないか |
| 名前 | 取り込み結果の素材名と絵が合っているか |
| 形の比 | `WARN` で比が違うと出ていないか。出たら小さく見えることをユーザーに伝える |
| 向き | 牛・犬・アヒルが横向きか。電車の前後が同じ形か(上の「アプリでの使われ方」) |
| 線の細さ | 細い線・細かい模様がないか(縮小すると見えなくなり、チラつく) |
| 絵柄 | 基準の車と同じ塗り方・丸み・色の雰囲気か |
| オリジナル性 | 既存のキャラクターや商品に似ていないか |
| 文字 | 文字・数字・ロゴが入っていないか |

`ingest` の出力に `WARN` や `NG` が出たら、その内容を必ずユーザーに伝える。

## 作り直し用の追記

同じチャットに送ってもらう文。問題に合わせて選ぶ。

| 問題 | 追記する文 |
| --- | --- |
| 背景が透明でない | 背景を完全に透明にして、もう一度描いてください。透明にできない場合は背景全体を単色のマゼンタ(#FF00FF)で塗りつぶしてください。 |
| 余計な物が描かれた | 指定した物を1つだけ描き、地面・背景の風景・ほかの物は描かないでください。 |
| 線が細い・模様が細かい | 細い線と細かい模様をすべてなくし、形をもっと太く大きく、単純にしてください。輪郭線は描かないでください。 |
| 絵柄がずれた | 最初に採用した赤い車の画像と、塗り方・丸み・色の明るさをそろえて描き直してください。 |
| 既存キャラに似ている | 特定のキャラクターに似ないよう、形と配色を変えた完全オリジナルのデザインにしてください。 |
| 文字が入った | 文字、数字、ロゴをすべて取り除いてください。 |
| 角度が違う | 角度は(プロンプトにある角度)にそろえてください。 |
| 形の比が違う | 物の形を(プロンプトにある「物の形は〜」の比)にして描き直してください。 |
| 動物が正面を向いた | 体は右を向いた横向きにして、顔だけ少しこちらに向けて描き直してください。 |
| 電車の前後が違う | 前と後ろをまったく同じ形(両端とも丸い)にして描き直してください。 |
| 複数枚ぶんが1枚にまとまった | 1つの物だけを、画像の中央に大きく1つ描いてください。 |

## コマンド一覧

| コマンド | 内容 |
| --- | --- |
| `sync-check` | `assets.json` とアプリのコードの素材(名前・保存先・縦横の比)が合っているか。ずれていれば `NG` |
| `chatgpt-list [--part N]` | 「次」ループでChatGPTに貼る文(決まり+番号付きリスト)。未着手の素材だけを約16点ずつに分けて出す |
| `inbox-preview` | inbox の画像を番号付きの一覧にし、`ingest --all` したときの割り当てを表示する |
| `status` | グループごとの進捗と次の素材 |
| `prompt <素材ID>` | その素材の完成プロンプトを表示(形の比と画像の形も入る) |
| `ingest [--sheet <素材ID>]` | inboxの画像(1枚)を取り込み、透過処理・比をそろえてWebP保存。省略時は、ファイル名が素材IDならその素材、違えば未着手の最初の素材 |
| `ingest --all` | inboxの画像をファイル名の順に、未着手の素材へ順番に取り込む |
| `approve <素材ID またはグループID>` | 完了にする。グループIDなら、そのグループの確認待ちをまとめて完了 |
| `reset <素材ID>` | 未着手に戻す |
| `check` | 必要な素材がすべて揃っているか |
| `preview-all [--group <グループID>]` | 取り込んだ素材の一覧画像 |

## 保存先(すべてリポジトリ内)

| 保存先 | 中身 |
| --- | --- |
| `inbox/` | ユーザーがアップロードする場所。取り込むと画像は削除される |
| `assets/img/<dir>/<name>.webp` | アプリが読む素材 |
| `assets/icons/icon-*.png` | アプリアイコン |
| `assets-src/reference/style_reference.png` | 基準の車(別チャットで添付し直す用) |
| `assets-src/preview/` | 確認用のプレビュー画像 |

元画像は基準の車以外は残さない(リポジトリが重くなるため)。元画像はChatGPTの履歴とiPhoneの写真に残っている。`assets-src/` と `inbox/` はNetlifyには公開されない(`netlify.toml` でアプリのファイルだけを公開している)。ただしGitHubのリポジトリは公開なので、`inbox/` と `assets-src/` の画像はGitHub上では誰でも見られる。家族の写真など、公開したくない画像は上げないようユーザーに伝える。

## 注意

- **アプリのコードで素材を足したり、大きさ・比を変えたりしたら、`sync-check` で `assets.json` とのずれを確かめる。** コードが正。`assets.json` の `name`・`dir`・`aspect` をコードに合わせる
- 素材の名前と保存先は DESIGN.md 13.2 の表とも一致させる
- 素材の中身(プロンプト)を変えたいときは `assets.json` を編集する。共通の絵柄指定は `style`、`palette`、`background` にある
- 取り込み時、画像の中の物のかたまりを1つにまとめて切り出す。離れた部品(気球のかごなど)は自動で1つにまとめ、`WARN` で知らせる
